CircuitBreaker 执行与状态速查

看到装饰器、HALF_OPEN、AtomicInteger 或 FAILED/BLOCKED 的时候，用这一页迅速定位概念。

一眼看懂执行顺序

originalAiCall = () -> { ... };   // 创建任务，不执行
decorated = CircuitBreaker.decorateCallable(cb, originalAiCall);
// 执行时才检查许可（不是包装时）
result = decorated.call();
// 获准 → 执行原任务 → 记录结果
// 拒绝 → CallNotPermittedException，原任务不会执行

状态 + 许可

状态是否执行下一步
CLOSED正常允许最少 4 次，失败率 ≥ 50% → OPEN
OPEN直接拒绝达到等待时间后，下一次请求可触发 HALF_OPEN
HALF_OPEN只允许 2 次试探许可两次结果完成后评估是否 CLOSED/OPEN

结果分类

SUCCESS

执行了原任务，正常返回。

FAILED

执行了原任务，抛出异常。

BLOCKED

没有许可，原任务没执行。

第 4 次失败而触发 OPEN：第 4 次 FAILED，第 5 次（立即到来）BLOCKED。异常先被装饰层统计，后被业务代码捕获。

HALF_OPEN：一轮两次，不循环补位

A 获许可并成功，B 获许可仍执行中；C 到来时仍 BLOCKED。两个名额限制本轮试探总次数，不等同于 Bulkhead 的可复用并发槽位。

AtomicInteger

表达式含义
new AtomicInteger()初值 0
incrementAndGet()原子加 1，返回新值
getAndIncrement()返回旧值，随后原子加 1
get() / set(0)读取 / 置零

单个原子操作是安全的，多步组合不自动原子；仅同一 JVM 内共享，跨实例要用共享存储。

实验关键参数

COUNT_BASED · slidingWindowSize=4 · minimumNumberOfCalls=4 · failureRateThreshold=50% · waitDurationInOpenState=5s · permittedNumberOfCallsInHalfOpenState=2
